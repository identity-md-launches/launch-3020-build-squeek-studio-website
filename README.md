# Squeek Studio

A static, unofficial creative studio for fully on-chain Squeek NFTs on Ethereum Sepolia. Preview any token without connecting, or connect a browser wallet to find held and deposited Squeeks. Make profile pictures, X banners, wallpapers, six transparent stickers, and a detailed Squeek ID card. Rendering and downloads happen locally; there is no backend, token, payment, approval, or transaction flow.

The deployable site is **`dist/`**, included alongside the TypeScript source and `package-lock.json`. Hosting does not require a build server. Vite uses `base: './'`; assets are relative and navigation uses hashes, including `#/studio/1`, `#/squeek/1`, `#/gallery`, and `#/about`. It works under a gateway subpath. Serve over HTTP(S), rather than opening `index.html` with `file://`.

## Install, run, and rebuild

Use Node.js 22.12+ (or 24), npm, and Python 3 for the downloadable source archive. Snapshot refreshes also use `curl`.

```sh
npm ci
npm run dev

npm run typecheck
npm test
npm run source
npm run build
npm run preview
npm run audit
```

`npm run source` creates `public/source.zip` from source, configuration, lockfile, documentation, license notices, and the required public assets. It deliberately excludes itself, dependencies, caches, scratch work, and `dist/`. The footer's Source code link downloads this complete rebuildable archive without needing a repository URL. Run it again after source or documentation changes, then rebuild.

The runner and Vite configuration also support dependencies installed under `test/scratch/node_modules` for restricted contributor environments. Normal installs resolve from the repository's regular `node_modules`. Neither dependency tree is submitted.

## Formats

| Format | Export size | Behavior |
| --- | --- | --- |
| Profile picture | 1000 × 1000 | Circle-safe guide centered at (500, 500), radius 460; name, handle, and seal sit within that area. |
| X banner | 1500 × 500 | Art and text occupy the right 60%; the bottom-left 600 × 200 region is marked as the avatar overlap zone. |
| Phone wallpaper | 1170 × 2532 | Character below the clock area. |
| Desktop wallpaper | 2560 × 1440 | Wide composition with centered artwork. |
| Sticker pack | Six 512 × 512 PNGs | Happy, sleepy, running, gm, wen merge, zoomies; downloaded together in a ZIP. Transparent outside the character, label, and preview tag. |
| Squeek ID card | 1200 × 750 | Art, name, all 11 traits, trait percentages, rarest-trait highlight, level, custody, staked days, short holder, and a local QR code to `#/squeek/<id>`. |

All images are PNGs. Canvas uses `imageSmoothingEnabled = false`. The SVG's glyph paths, positions, group colors, and opacity are reconstructed directly; sticker poses move/recolor these same glyphs rather than replacing the Squeek with stock artwork. Preview guides are HTML overlays and never enter the PNG. Preview exports include a corner tag.

Downloads use blob URLs. Copy image uses `ClipboardItem` where available (the first sticker for a pack). Native file sharing uses `navigator.share`; after generating files, browsers that require a fresh user gesture ask for a second Share file selection. Files generated by Download are also ready to share. Share on X opens the provided intent endpoint with text and the public Squeek page URL. These links are explicit navigation, not automatic background requests.

## Eight templates and real-data decorations

The original, In orbit, Dot matrix, Paper cut, After hours, Postcard, Soft bloom, and Signal are drawn in code. Background tints are mixed from actual SVG colors; Cross Grid, Dot Grid, Micro Dots, Wide Dots, and Scanlines echo the Background attribute. Custom backgrounds, art size, nickname, handle, name visibility, badges, and guides are adjustable where applicable. Sticker packs use the original Squeek palette and expose art size; irrelevant background and template controls are hidden. Banner teams contain up to five Squeeks from the connected wallet, with each member checked again before export.

Decoration rules are explicit choices in `src/lib/core.ts`:

- Level 1–2: bronze; 3–4: silver; 5–7: gold; 8+: neon. Unknown level produces no frame.
- Current staking periods of 7, 30, and 90 days unlock different ribbon colors; the ribbon prints the actual day count. Unknown age does not become zero and produces no ribbon.
- A rarest trait strictly below 2% enables the iridescent foil frame and Rare label. Exactly 2% does not qualify.
- Only a fresh API `ACTIVE` measurement enables the Wheel live glow. The status is fetched again when files are generated and its UTC observation timestamp is printed. Failed, stale, or unknown readings produce no glow.

## Read-only data

All chain configuration is in `src/lib/chain.ts`:

| Source | Fields / use |
| --- | --- |
| ERC-721 `0xc4c7982657f00509548f3a3a41db7fa439a6856b` | `tokenURI`, `ownerOf`, `totalSupply`, `balanceOf`, Transfer events. Chain ID **11155111**. |
| Staking `0x50fd1780526c3186a0c037c7622203bc4fb611ca` | `depositor(collection, tokenId)`. Staking custody is distinguished from the depositing holder. |
| Multicall3 `0xcA11bde05977b3631167028862bE2a173976CA11` | Batched ownership/depositor reads; bounded metadata reads; snapshot batches split when renderer gas limits are reached. |
| `https://api.squeekchain.com/v1/accounts/{address}` | Paginated token IDs, level, custody details, merge state. API data does not override current on-chain ownership. |
| `/v1/accounts/{address}/activity` | Paginated deposits/withdrawals with `source.blockTimestamp`; earliest deposit in the current staking period determines full elapsed days. |
| `/v1/status` | `measurement.coreStatus`, `rpmMilli / 1000`, observation freshness, and builder anchor block height. |
| `/v1/economy/state` | Issued-ID bound for fallback ownership scans. No token/economy trading interface is exposed. |

RPC fallback order, with 10-second timeouts per endpoint:

1. `https://ethereum-sepolia-rpc.publicnode.com`
2. `https://sepolia.gateway.tenderly.co`
3. `https://1rpc.io/sepolia`

A wallet's candidate set combines all incoming Transfer events, current depositor checks across every historically deposited ID, and every API token page. Scanning depositors also covers a deposit made by an operator whose address differs from the Transfer sender. Owner/depositor multicalls validate candidates. If event indexing fails, a bounded issued-ID scan checks ownership directly. Cached wallet results are explicitly marked when a live check fails. The gallery finds the latest 100 distinct Squeeks from Transfer events, in descending event order, and filters their actual loaded traits. Burned or unavailable artwork is skipped with a count.

Big decimal block IDs remain strings or `bigint`; unavailable API values remain unknown. Level is a bounded numeric field. API indexing can lag the chain: current staking custody may be known while deposit age is still unknown. This does not produce a zero-day badge.

## Rarity snapshot and refresh

`public/traits-snapshot.json` is a compact **attributes-only** snapshot. Metadata includes the exact block number, block timestamp, source, circulating supply, highest issued ID, and burned IDs. `traits` is the column list, and `tokens[id]` is the corresponding array of trait values. Images are only in the separate six-token `examples.json`, never in the rarity snapshot.

The delivery snapshot contains **9,096 Squeeks at Sepolia block 12073886**, dated **2026-11-06T03:23:48.000Z**, with 903 confirmed burned IDs excluded. Its immutable trait cache was read at blocks 12073656, 12073886.

`totalSupply()` is circulating supply, not the highest ID, because Squeeks can burn during merges. The snapshot script reads IDs 1 through totalSupply and continues through the highest mint ID from Transfer events. It checks failed tokenURI calls against `ownerOf`, splits expensive multicalls, excludes confirmed burns, and requires the final readable population to equal totalSupply at the fixed block. It never labels a gas failure as a burn without an existence check.

For each trait, rarity is `count(trait_type, value) / snapshot_population`. The rarest trait is the smallest such share. New Squeeks are read live and scored against the same population; a new unseen value has a 0% baseline share. There is no market-price score. The UI and ID export state **Rarity as of block N**. Missing or unreadable snapshots disable percentages and rarity decorations while leaving the studio usable.

```sh
# Start a fresh fixed-block snapshot (can take substantial RPC time).
npm run snapshot -- --fresh
# Resume an interrupted snapshot at its original fixed block.
npm run snapshot
npm run source
npm run build
```

The checkpoint is disposable `test/scratch/snapshot-checkpoint.json`; it is not shipped. If providers prune an in-progress historical block, `npm run snapshot -- --rebase` selects a fresh fixed block, verifies ownerOf for every issued ID, removes newly burned tokens, and reuses only immutable attribute reads. The snapshot records those attribute-read blocks in `immutableReadBlocks`; the population and displayed rarity block refer to the newly verified block. A full fresh scan is also available. The six landing examples are refreshed from the first real Squeeks during a fresh run.

## Wallets, privacy, and safety

Browser wallets are discovered by EIP-6963, showing their own names and data-URI icons. A legacy EIP-1193 browser provider is a fallback. Mobile browsers offer explicit links to open the same page in MetaMask, Rabby, Coinbase Wallet, or Phantom. The Rabby URL uses the `open-dapp` command and `dapp` query parameter from its [official universal-link handler](https://github.com/RabbyHub/rabby-mobile/blob/develop/apps/mobile/src/hooks/universalLink.ts). Wallet restoration uses `eth_accounts`; a deliberate connection uses `eth_requestAccounts`. A wrong chain offers Sepolia switching/addition.

The brief's strict network allowlist takes priority over the pinned guide's Coinbase Smart Wallet SDK suggestion: no SDK relay, WalletConnect project ID, or additional background service is included. Coinbase's injected browser wallet can connect like any other EIP-1193 provider.

Optional verification calls **only** `personal_sign` with:

```text
Squeek Studio | I hold Squeek #ID | <ISO date>
```

viem verifies the recovered EOA signer against the connected address. A short `keccak256(signature)` fingerprint appears in the seal. Ownership is checked before signing and again before export, including the staking depositor. Account/chain/Squeek changes reset verification. Signatures stay in memory, are not uploaded, and do not prove future ownership. No approvals, transfers, transactions, private-key inputs, or seed-phrase inputs exist.

“Nothing leaves your browser” refers to artwork edits, nicknames, signatures, and generated files. Public RPC/API providers necessarily receive the addresses and token IDs being looked up and ordinary connection metadata. There is no analytics or tracking. A Content Security Policy restricts background connections to the listed endpoints and same-origin static assets; CCIP reads are disabled. Wallet icons cannot load arbitrary remote URLs.

Immutable artwork and traits are stored per ID in IndexedDB. Facts and wallet lists have an explicitly cached fallback; old ownership cannot grant a new seal. Storage failures fall back to memory. A previously cached Squeek can still be previewed while RPC/API providers are offline; this is not a promise to load the application shell without network access on a first visit. There is no service worker or backend.

## Validation

Run the pure-function tests and production checks:

```sh
npm test
npm run typecheck
npm run build
# Optional rendered interaction checks; requires Playwright Chromium and curl.
npx playwright install chromium
npm run check
```

`npm run check` starts and closes its own temporary static server, serves the actual export under `/preview/`, and closes its single browser in `finally`. `SQUEEK_BROWSER_EXECUTABLE` can select an already installed Chromium binary. Its RPC/API bridge uses curl to the exact allowed public endpoints when the contributor sandbox's browser network cannot reach them directly. It does not substitute fake chain data. Results, temporary downloads, and screenshots go only to `test/scratch/`.

The worker ran production builds, TypeScript checking, eight pure-function tests, rendered primary interactions, actual PNG/ZIP checks, wallet-provider simulations with real public on-chain reads, QR decoding, and the pinned taste@1 review. Actual final counts, fixes, evidence, and limitations are recorded in **`artifacts/validation.md`**. The supplied browser tool could not find its Chrome distribution; an available headless Chromium binary was used instead. WebKit could not launch because `liblcms2.so.2` is missing. Physical-device sharing, real extension approval, a real holder signature, and native screen-reader/200% browser zoom sessions remain unperformed.
